Privacy-first monitoring · on-device AI

A house that notices, asks, and acts.

QNet Home is a monitoring system for the people who need watching over — a child, an elderly parent, someone recovering from surgery, or an empty house at 3am. Rooms sense and speak locally. Devices exchange small semantic JSON events over MQTT. No video, no audio, ever leaves the room it was captured in.

It doesn't just watch. It acts: it speaks to the person, listens to the answer, messages a trusted contact, and escalates to an emergency call when nobody replies.

Monitor, and act

Most home monitoring stops at the notification. A camera sees something, a phone buzzes, and a human somewhere has to work out what it meant and what to do. That gap — between detection and response — is where the minutes go.

QNet Home closes it. The same event that lights up the dashboard also opens a conversation in the room, starts a timer, and puts a named human on the hook with a deadline. Nobody is left in silence, and no step depends on someone happening to look at their phone.

👶 Child

Is a toddler on the floor and not getting up? The room asks, listens, and escalates to a parent if it hears nothing back.

🧓 Elder care

The canonical case. A fall with nobody home is measured in hours, not minutes. Here it is measured in seconds, and the escalation runs itself.

🏥 Medical

Post-operative or mobility-impaired residents. Sourced first-aid guidance is spoken from the skill file — calm, one instruction at a time, never invented by a model.

🔒 Security

The event fabric is generic. Any room node can publish any event kind; the skill file decides what the house does about it.

Fall Detection & Safety Monitoring

System-initiated and urgent. The room notices a fall on the NPU, asks "Are you okay?", listens, and climbs an escalation ladder — reassurance out loud, a Telegram to a trusted contact, an emergency call if there is still no answer — narrating every step.

Where the work happens is the whole design. Heavy language reasoning needs one capable device, so it lives on the IQ9. Perception has to happen where the photons and the sound are, so it lives on the Ventuno Q nodes. The laptop is the human's way in — the hub where you watch the house and push changes to it.

Four principles

1. The agent runs the conversation; the engine guarantees what must not fail

Timers, contact notifications, and the emergency call are automatic — enforced in code, not requested from a model. A slow or wrong LLM can only ever make the small talk worse, never the response. The system runs correctly with the model switched off entirely.

2. Privacy by construction, not by policy

Nodes publish semantic JSON, never media. The vision model that finds your glasses runs inside the room and emits a sentence. There is no frame to intercept, because the frame never went anywhere. The only thing that leaves the house is a message to a caregiver.

3. Skills are data

Each capability is a markdown file of phases and guidance. Adding one touches no engine code. The escalation ladder, the timers, and the exit conditions are all editable text — validated at startup, so a typo fails when the agent boots rather than at 3am mid-incident.

4. Measured, not asserted

Every performance number in this project is tagged measured or unmeasured, with the method written down. Failures are documented alongside the wins — the NPU contention, the TTS hang, the dropped-speech investigation and its fix.
