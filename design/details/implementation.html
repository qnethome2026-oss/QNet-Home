Implementation

The agent decides. The engine guarantees.

This is the load-bearing idea of the whole system. A 2-billion-parameter model running on an NPU is good enough to classify a reply and word a sentence. It is not good enough to be the thing standing between a person on the floor and an ambulance. So it isn't.

The split, precisely

What the model may do

  • Classify a person's reply into one of the options the current phase already allows
  • Word a comfort-loop update from facts the engine hands it
  • Word the first-responder brief from a session log it is given
  • Flag a garbled transcript as unclear

What only the engine may do

  • Fire a timer, and act when it expires
  • Send a trusted-contact notification
  • Place the emergency call
  • Match a cancel phrase, or a contact's OK reply
  • Decide which phase the session is in
  • Word any answer whose content is itself the safety claim

This is testable, and tested. --no-llm is byte-for-byte the same code path the system always had — no client is constructed, so not one branch differs. The full escalation ladder runs correctly with no language model present at all. The model is an enhancement to the conversation, never a dependency of the response.

A case where this mattered

During live testing, an object search came back with no room answered. Gemma worded the result as: "The item is in the living room. The living room camera reported that the item is there." A fabricated location, spoken aloud, with a fabricated citation.

The fix was not a better prompt. The fix was recognising that the search answer is that skill's safety content, and moving it permanently onto the rails. Those sentences are now deterministic and the model is not consulted. Prompt engineering cannot make a guarantee; code can.

Skills are data

A capability is one markdown file. Frontmatter declares what it is, a single fenced YAML block declares the phases, and prose after ## Guidance is handed to the model as-is. Everything between them is commentary for the human editing the file — the loader ignores it. 

---
name: fall-response
trigger: fall.detected
urgency: safety            # safety takes over the dashboard; routine does not
source: IFRC 2020 First Aid Guidelines; AHA 2020 Highlights
emergency_number: "911"
---

## Phases
```yaml
- id: check
  opening: "I saw you fall. Take a breath — are you okay?"   # canned, spoken instantly
  goal: "Find out whether they are hurt or need help."
  tools: []
  exits:
    ok:       "they clearly say they are fine and deny pain or hitting their head"
    escalate: "they say no, ask for help, report pain, or do not respond"
  timer: { after_s: 30, goto: escalate }
```
opening
Spoken the instant the phase starts. Canned — no model call, so it is reachable even with the LLM down.
goal
What the model is trying to achieve this phase. Prose, not code.
tools
The allowlist. A tool call outside it is refused and logged as a refusal line.
on_enter
Actions that fire automatically the instant the phase starts — no agent turn involved.
exits
Named ways to leave, each with the condition in plain language.
timer
{after_s, goto}. A missing timer means no timer — that one line is the difference between a fall skill and a query skill.

on_enter is stronger than "the model should remember to"

An earlier design had a must field meaning "guaranteed before exit, enforced by the timer as a fallback." Reliable — but still routed through the agent's turn. on_enter removes the agent from the path entirely: the action fires when the phase starts. For notifying a caregiver and placing an emergency call, "instant and automatic" is worth being more explicit than "guaranteed eventually."

Validation is load-time and loud

A skill file is data, but it is data that decides whether a caregiver gets called. So a typo must fail when the agent starts — not silently do the wrong thing at 3am, mid-incident.

At load, the engine rejects the file unless:

  • every timer is {after_s: <positive number>, goto: <an existing phase>}
  • every exit name either matches a phase id (a jump) or is a declared terminal state
  • every on_enter action exists in the tool registry
  • every name in a phase's tools: allowlist exists in that same registry

The subtle one. The runtime rule for exits is elegantly simple: an exit whose name matches a phase id jumps to that phase; any other name ends the session with that label as its final state. That rule alone makes every name legal — which would turn the typo escalat: into a silent session close instead of an escalation. The single most dangerous failure this codebase can produce.

So the loader also keeps a vocabulary of known terminal states. A name that is neither a phase nor a known terminal state is a load error. The runtime rule is unchanged; the typo now fails at boot.

The session loop

The interrupt that isn't a session

A first responder walking into the room says "I'm the first responder — what happened?" and gets a spoken handover: condition first, then what was done, then where things stand.

This is deliberately not a session. It is an engine-level interrupt: pause the comfort loop, read the room's latest fall log, one model call to word the timeline, speak it, resume. Because it never enters the session table, the one-session-per-room rule cannot block it — a responder can always ask, even mid-escalation. The responder phrase is checked before the wake phrase, in any state.

Every session writes itself down

One stream, two destinations — not two mechanisms. Every log line is appended to data/sessions/<room>__<skill>__<started_at>.jsonl and published to qnet/session/<id> the instant it happens.

Log eventRecords
detectedThe triggering event kind and its confidence
sayEvery line the house spoke
heardEvery transcript, including timed-out silences
phaseEach transition, from → to
toolEach tool call and its result
refusalA tool the model asked for outside the phase allowlist
contactA trusted contact's reply, verbatim, by configured name
briefA responder brief — exactly one line, only into a file that already existed

The refusal line is worth dwelling on. When the model asks for a tool the phase doesn't allow, the request is denied and written down. The record of what the model wanted to do but wasn't permitted to is as valuable as the record of what happened.

Tests

207 hermetic tests — no broker, no hardware, no network — running in about 85 seconds on a laptop with nothing plugged in. A further 7 are marked live and opt in to the real Gemma endpoint. The suite covers the skill loader's validation rules, the contact-ack rails, the find flow, the responder brief, the vision gate logic, contract conformance against the fixtures, and full scenario walks of the escalation ladder.

The failures are written down too

  • NPU contention is real. The inference CLI intermittently fails when a second container is using the accelerator. Retried ×3 with backoff; it rides through.
  • A dropped-speech investigation. Of roughly 7 listen windows opened in one session, exactly 1 survived to publish a transcript — the engine was republishing the session document on every log line, and each snapshot cancelled the node's in-flight listen. Fix: ignore snapshots that don't flip the node's mode. Cancelled listens went from ~19 to 1; transcripts published went from 1 to 3 plus a clean silence.
  • A 30-second TTS hang made a node deaf and mute from second zero of a session. Documented, with the watchdog deliberately deferred as higher-risk than the bug.
  • Threshold honesty. A confidence floor of 0.35 fires on a blank wall. It was restored to 0.6 and the evidence recorded — including that photo-of-a-fall replay sits in the same confidence band as wall noise, so it is not a viable trigger.
