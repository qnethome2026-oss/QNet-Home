Design

One fabric, three tiers, no backend.

Every device does the one job only it can do, and the only coupling between them is a topic name on an MQTT broker. There is no REST API, no message schema negotiation, and no service discovery — a node that boots starts publishing, and the house notices.

The three tiers

The split is not arbitrary. It follows from a single question asked of every workload: what does this computation need to be near?

Edge · 2× Ventuno Q

Near the photons

Perception must happen where the camera and the microphone are — that is the entire privacy argument. If a frame has to travel to be understood, it can be intercepted, logged, or subpoenaed. So it doesn't travel.

Runs: camera capture, fall detection (YOLO11n, Hexagon NPU), the room's own VLM via the LLM-VLM microservice (Qwen3-VL-4B, w4a16), ASR/STT (Whisper-small on NPU), TTS (Piper), and the wake-phrase gate.

Brain · IQ-9075

Where the reasoning is

Language reasoning is the one workload that genuinely wants a single capable device. Running a general LLM on every node would multiply cost and memory for no gain — there is only ever one conversation happening at a time.

Runs: Gemma 4 E2B on the Hexagon NPU via GenieX (OpenAI-compatible on :18181), the agent engine, the skill files, the tool registry, and the Mosquitto broker that everything else talks through.

Hub · Laptop

Where the human is

The hub is the operator's seat: the floor plan, the live feed of what the house is doing, the incident banner with one-click resolve, and the place deploys are driven from. It is a pure subscriber — nothing depends on it being switched on.

Runs: the dashboard (a single HTML file over MQTT websockets, no build step and no backend), the bring-up and deploy scripts, and the packaged Windows app.

Terminology note. These pages call the laptop the hub — the human's control point for the house. In docs/DESIGN.md and the repository README, the word "hub" refers to the IQ-9075 as the message hub. Same topology, two vantage points: the IQ9 is the centre of the fabric, the laptop is the centre of the operator's view.

The wire contract

MQTT topics are the only interface in the system, and they are frozen: any change to a topic or payload updates contracts/mqtt.md and the JSON fixture in contracts/fixtures/ in the same commit, or it didn't happen. Three separate consumers read those same fixtures, so a drift breaks a test rather than a demo.

TopicDirectionQoSCarries
qnet/<room>/eventnode → agent1Something happened — a fall, with confidence and the N-of-M that fired
qnet/<room>/asknode → agent1A question — an object query, or a first-responder brief request
qnet/<room>/sayagent → node1Speak this, with a priority: safety · comfort · routine
qnet/<room>/heardnode → agent1The transcript, or silence: true when the listen window timed out
qnet/lookagent → all1Look for X right now — a broadcast on one unqualified topic
qnet/<room>/lookednode → agent1What that room's VLM saw, as one sentence
qnet/<room>/statusnode → all0Heartbeat every 5 s — how the dashboard learns which rooms exist
qnet/<room>/contactagent → all1A trusted contact's Telegram reply, republished onto the fabric
qnet/session/<id>agent → hub1The live session document, including its full log

Why those QoS levels

Everything that carries a decision or a person's words is QoS 1 — losing a fall event, a spoken line, a transcript, or a search result changes what the system does or fails to say. status is a repeating heartbeat, so QoS 0 is correct: the next one is along shortly and a dropped beat costs nothing.

Room identity comes for free

A question arriving on qnet/kitchen/ask gets its answer on qnet/kitchen/say. That single fact removes an entire category of complexity: no person tracking, no speaker localisation, no cross-room correlation. The topic is the addressing.

Failure behaviour

Designing for a house means designing for the day something is unplugged.

What breaksWhat happens
The LLM is down or slowEvery phase has a canned opening line and the engine's own deterministic sentences. The escalation ladder is unaffected. --no-llm is a supported, tested mode.
A room node is offlineThe agent knows how many rooms it expects from house.yaml, so it says "I couldn't reach the bedroom" rather than silently reporting not-found.
The hub (laptop) is closedNothing changes. It is a subscriber. The escalation, the Telegram, and the emergency call all run without it.
Telegram is unconfiguredNotifications fall back to the console and a log file. Everything else works.
The NPU call failsRetried three times with backoff — a measured, real failure mode when the accelerator is shared between containers.
A contact acknowledges then goes quietA 180-second backstop timer still places the emergency call. An acked incident is never a stranded one.
