Platform

Everything inferences on-device.

Five models across three devices, all of them running on Qualcomm Hexagon NPUs. Nothing is a cloud API call. The stack below is what makes the privacy claim structural rather than aspirational — there is no remote endpoint to leak to, because there is no remote endpoint.

IM SDK — the multimedia and vision path

The Qualcomm Intelligent Multimedia SDK is a hardware-accelerated multimedia and AI framework built on GStreamer. Its job is to give an application access to the full processing capacity of the SoC — the neural processing accelerators, the video encode/decode blocks, the camera ISP, the GPU, the display, and the audio DSP — behind a plugin-based architecture that abstracts the hardware away.

That abstraction is what lets a room node treat "a camera frame" as a pipeline element rather than a driver problem. QNet's fall detector and VLM both consume frames from this path, and the node exports the latest frame to shared memory so the two consumers never contend for the camera device.

A real deployment gotcha, recorded. The vendor EVK image ships with a pre-existing broken apt dependency set around the qimsdk-cpp and python-gstreamer1.0-qcom packages — they require a newer libgstreamer-qcom1.0-0 than the configured repos carry. Every plain apt-get install aborts as a result.

Do not run apt --fix-broken install. Since the newer package isn't available, apt "fixes" it by removing the IM SDK / GStreamer stack — which is exactly what the room node's vision path depends on. The workaround used throughout this project: apt-get download <pkg> && sudo dpkg -i <pkg>.deb, which installs cleanly without touching the broken set.

GenAI microservices — the Audio Analytics container

Qualcomm's Audio Analytics container bundles three on-device services — automatic speech recognition, text-to-text translation, and text-to-speech synthesis — into one deployment, with every model running on the NPU so the CPU stays free for application work. It runs via Docker Compose on the IQ-9075 and IQ-8275 EVKs, with models mounted as read-only volumes.

Models it serves

  • ASR — Whisper Small (and a quantized variant), English / Spanish / Chinese at 16 kHz
  • Translation — OpusMT bidirectional, EN↔ES and EN↔ZH
  • TTS — MeloTTS (EN/ES/ZH, 44.1 kHz) and PiperTTS (EN/DE/IT, 22.05 kHz)

API surface

REST and WebSocket on port 8085, with a Swagger UI at http://<device-ip>:8085/docs:

  • /audio-analytics/v1/api/health
  • /transcriptions/create — batch and streaming
  • /tts/synthesize
  • /translations/translate

The WebSocket path is what makes real-time transcription possible rather than file-at-a-time batch processing.

QNet reaches this runner through the Arduino App Bricks asr and tts bricks rather than calling the HTTP API directly — the App Lab application owns the containers, the model provisioning, and the audio devices as one unit. The important property is the same either way: the audio never leaves the board.

ASR — how the room listens

The deployed nodes run float Whisper-small, with the audio-analytics runner resolving the name from its model registry and executing the QNN encoder and decoder on the Hexagon HTP. The board's built-in whisper-small-quantized works out of the box and remains registered as a rollback — switching is a config flip and a restart, not a re-download.

SituationCall usedWhy
Idle — waiting for "Hey Home" transcribe_until_cancelled() One stream stays open and yields repeated partial/final events, so there is no blind gap between utterances
Inside a live safety session transcribe_sentence(timeout=…) Returns on the first finalized utterance or the hard timeout — the agent is waiting on an answer, not monitoring

Endpointing

The ASR client creates every session with a VAD parameter — the verified default is 700 ms. The runner emits speech_start, speech_end, partial-text and full-text events, which gives sentence endpointing without a second VAD model or a second owner of the microphone.

Silence is a result, not an error

When a session produces no text at all, the collector returns an empty string and QNet maps it onto the wire contract as: 

{"text": "", "silence": true}

That distinction matters to the escalation ladder — silence is meaningful, and it advances the fall skill. Genuine failures (service unavailable, audio device wedged, session busy) are errors reported through node status, never quietly converted into silence.

Cancellation, and why every listen is tagged

asr.cancel() does not guarantee an empty result — the collector deliberately falls back to the most recent partial transcript when no final one arrived. So the voice controller tags each listen generation and discards every result from a generation that was cancelled to make room for speech. Inferring cancellation from an exception alone would be wrong.

While idle, the node retains at most 10 seconds of finalized text plus the latest partial — enough to preserve a short "Hey Home" that Whisper sometimes omits from the final event. The buffer is cleared before every TTS playback, so the speaker's own output can never be stitched onto a later user request.

TTS — how the room speaks

tts.speak(text) is synchronous in the installed implementation: it holds a session lock, streams synthesis results, and writes all PCM chunks to the ALSA speaker before returning. Concurrent calls on the same object raise a busy error.

The library does not explicitly drain the final hardware playback buffer after its last ALSA write, so QNet holds a configurable post-TTS guard, 500 ms by default, before reopening the microphone. Without it, the tail of the house's own sentence can be transcribed as the person's reply.

The half-duplex invariant

This is why the hardware list says no echo cancellation needed. The node is half-duplex by design, so the speaker and the microphone are never live at the same instant and there is no echo to cancel. The cost is honest and documented: the node is deaf while it is speaking, and barge-in is impossible. Measured deaf windows ran 2.3–10.1 s per line, and up to 15.2 s continuous when a safety line and a comfort line chained back-to-back.

GenieX — the LLM runtime on the IQ-9075

GenieX serves Gemma 4 E2B-it (Q4_0 GGUF, 4.0 GiB on disk) as an OpenAI-compatible endpoint on http://127.0.0.1:18181/v1 — localhost-only, since the agent runs on the same board. It is installed natively and managed by systemd, so it comes back after a reboot and after a crash.

Measured on QCS9075. Decode throughput ~15.7–16.2 tok/s over six ~200-token generations. Time to first token, model warm: ~0.18 s. First request after service start (model load included): ~12 s. Model RAM footprint ~4 GB of 34 GB available — no pressure.

The design budgeted 1–3 s per agent turn. At 16 tok/s a one-sentence spoken line of ~25 tokens is about 1.7 s — inside budget. Confirmed on the NPU, not the CPU: the service log shows the Hexagon backend loading onto FastRPC.

Three findings that shaped the agent

Building against a runtime at v0.3.18 meant discovering its edges. All three of these are the reason the engine/model split described in Implementation is drawn where it is.

1. Thinking is on by default, under non-OpenAI field names

Responses came back containing Gemma 4's raw reasoning inline, and the shortest prompts ("hi") thought the longest — sometimes never leaving the thought channel. The controls exist, but not under the names an OpenAI client would send, and unknown fields are silently accepted:

What you wantSilently ignoredActually works
No thinkingthink: falseenable_think: false
Token capmax_tokensmax_completion_tokens

2. Native tool-calling does not work on this version

Given a tool list and a prompt demanding tool use, the model correctly decides to call the tool and emits Gemma 4's native syntax — but the server returns it as plain content and tool_calls stays null. tool_choice: "required" behaves identically to "auto".

Design consequence: nothing in QNet may depend on the model emitting a tool call. The object search fires on phase entry as an engine action instead — the phase's tools: allowlist is still declared and still enforced, but the broadcast does not wait on the model to request it.

3. Structured output crashes the server

ApproachResult
GBNF grammar fieldAccepted and correctly enforced — but the next generation crashes the server
response_format: json_schemaCrashes instantly
response_format: json_objectAccepted, not enforced
enable_json: trueCrashed in testing; treat as unsafe

So the structured-output guarantee is implemented as prompt + strip + validate + retry in the LLM client — validate the answer against the expected enum, retry once on mismatch — and the engine's phase allowlist refuses anything invalid regardless. Grammar is the right mechanism and demonstrably constrains correctly; it gets re-tested when a fixed release ships. systemd restarts the server in ~10 s either way.

A fourth, worth knowing if you reproduce this. GenieX detects Gemma 4 E2B as a VLM (it ships a vision projector), and v0.3.18 has a VLM-path tokenization bug that silently corrupts text-only prompts to VLM-typed models — the model generates fluently while ignoring the prompt entirely, with prompt_tokens: 1 on every response. The workaround is to force the plain-LLM code path in the model's cache metadata. QNet loses nothing by doing so: the brain only ever sends text, because the VLM work happens on the room nodes.

The VLM on the node

Qwen3-VL-4B (w4a16) runs on the Qualcomm LLM-VLM microservice on each Ventuno Q, answering the smart-object-discovery broadcast. Frames are downscaled to roughly 640 px before the model sees them — never native camera resolution. Downscaling is nearly free and is the single biggest lever on query latency.

The node is already running a camera pipeline for fall detection, so a look takes the latest frame already in memory — no second capture path, no rolling buffer. Measured round trip, board to broker to board including the frame grab and the VLM call: 4.13 s median, with the VLM call itself 3.3–4.5 s of it.

Sharing one NPU

On a room node, fall detection, the VLM, and Whisper all want the same accelerator. This is not free, and the project measured what it costs:

  • The inference CLI intermittently fails (and once produced a ~1 minute burst of FastRPC transport errors) while the VLM and voice containers are active — each invocation opens a fresh FastRPC session. The identical call succeeds on retry; the detector retries ×3 with 0.2 s backoff and rode through it.
  • Bringing the voice node up cost +1443 MiB of RAM, leaving 3761 MiB headroom — comfortably above the gate at which the quantized Whisper rollback would be needed.
  • Process-spawn overhead dominates single-frame inference: 34.8 ms of actual NPU execute inside a 307.7 ms call. Batching eight frames amortises it to 56.9 ms/frame — a 4.9× throughput gain, at the cost of up to half a second of added event latency. Single-frame stays the default for the live camera, because cadence matters more than throughput for a safety trigger.
