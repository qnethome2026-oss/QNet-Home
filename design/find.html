⏱ 1 min · use case 2

"Hey Home, where are my glasses?"

The calm inverse of a fall — person-initiated, no timers, two or three turns. Every room checks its own camera with its own vision model, and the answer is spoken where you asked.

3 · Model performance

This use case leans on two models per room — Whisper-small for the question, and the vision-language model for the answer. Both run on the Ventuno Q's Hexagon NPU.

The VLM dominates, so that is where the tuning went. Downscaling to ~640 px before the model is nearly free and is the single biggest lever — time-to-first-token grows steeply with input resolution. Reusing the frame the fall detector already captured saves a further 0.6 s per query. What's left is the model call itself.

Where the numbers stop. AI Hub publishes no fixed latency for Qwen3-VL-4B — for generative models it reports TTFT and response rate, both prompt-dependent, so there is no reference figure to compare our 3.3–4.5 s against. Our measurements are n=5 on one board with the NPU shared with fall detection and the voice stack, so treat them as directional. And nothing here measures accuracy — how often the VLM is right about where your glasses are is untested.

qid is the correlation key. A looked whose qid isn't the one just broadcast is dropped — reply topics are shared, and a late answer to the previous question must never be read as an answer to this one.

5 · Step by step, what actually happens

  • STEP 1 · Whisper-small on HTP · idle stream
    The node is already listening, locally

    transcribe_until_cancelled() keeps one ASR stream open with a 700 ms VAD, so there is no blind gap between utterances. Up to 10 s of finalised text plus the latest partial is retained — enough to keep a short "Hey Home" that Whisper sometimes drops from the final event.

  • STEP 2 · wake gate — a string comparison
    Match, or the transcript is discarded on the board

    No wake-word model. Lowercase, strip punctuation, require a "hey home" prefix with small edit-distance tolerance. On a match the remainder is published as an ask; on a miss nothing is published and nothing leaves the node. This is what stops one person asking another person "where are my glasses?" from triggering the house.

  • STEP 3 · engine.py · clause-cutting regex
    The object is extracted before the model is consulted

    "where's my X [anything after is noise]" is cut by regex, not by Gemma. Inbound traffic for rooms absent from config/house.yaml's rooms: map is dropped outright — a coexisting stack on a shared broker was publishing raw STT chatter as queries.

  • STEP 4 · phases.py loads skills/find.md · phase search
    A routine session opens — no timers

    Same loader, same validation, same refusal path as the fall skill. urgency: routine, so it never takes over the dashboard.

  • STEP 5 · look_in_rooms → qnet/look
    One broadcast, every node subscribed

    The search fires on phase entry, like an on_enter action — because SDK-native tool-calling doesn't work on this GenieX build, a phase whose entire job is one broadcast cannot depend on the model emitting a tool call. The allowlist is still declared and still checked.

  • STEP 6 · qnet/node/look.py · Qwen3-VL-4B (w4a16)
    Every room looks at once, in its own room

    The node reuses the frame already in memory from the fall-detection pipeline — no second capture path, no rolling buffer. Downscaled to ~640 px before the model, never native resolution. Each node returns one sentence; the frame stays put.

  • STEP 7 · collect · find.look_timeout_s = 6
    Return early, or answer with what arrived

    The agent knows how many rooms to expect, so it returns the moment the last one answers — the timeout is only ever paid for a room that is genuinely silent. Tuned from 8 s down to 6 s off measured data: worst observed node-side handling 5.4 s, plus margin.

  • STEP 8 · engine rails — deterministic wording
    The engine words the answer, not the model

    Three distinct outcomes, three distinct sentences, all assembled in code. Then say goes back on the topic the ask arrived on, with prio: routine.

  • FOLLOW-UP · last_find window, 120 s
    "I still don't see them" → phase guide

    A follow-up is a new ask, so one variable connects it: the agent remembers the last find result for two minutes. A new ask naming no object inside that window goes to guide, using the remembered object and whichever room the person is speaking from now. One variable, one if-statement — no conversation history, no session linking.

6 · The skill behind it

qnet/tools/look_in_rooms.py Broadcasts the look, correlates looked replies by qid, returns early once every configured room has answered, and reports which rooms actually replied — which is what makes the third outcome below possible.
qnet/node/look.py The room side: subscribe to qnet/look, take the shared-memory frame, downscale, prompt the LLM-VLM microservice, publish one sentence.

7 · Honesty is the feature

The model never words a search answer — because we watched it lie. The tool reported no room answered, and the model said: "The item is in the living room. The living room camera reported that the item is there." A fabricated location with a fabricated citation, spoken out loud.

The answer is this skill's safety content, so it moved permanently onto the engine's rails. Prompt engineering can't make a guarantee; code can.

Measured on the Ventuno Q, five runs, warm model. Round trip board → broker → board → frame grab → VLM → back: 4.13 s median (4.11 / 4.42 min–max). Node-side handling alone 3.9–5.4 s, of which the VLM call is 3.3–4.5 s. A direct camera grab costs ~0.6–0.7 s; the shared-memory frame path costs 0.02 s.
