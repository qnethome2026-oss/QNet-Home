# Guide 2 — The hub (Qualcomm IQ-9075 EVK)

**What you're doing:** turning the IQ-9075 into the house's brain — three
services, installed in order: the **LLM** (Gemma 4 E2B on the Hexagon NPU,
port `18181`), the **MQTT broker** (ports `11883`/`19001`), and the
**agent** (the engine that runs the conversation and the escalation ladder).

**You need:** an IQ-9075 EVK with the vendor Ubuntu 24.04 image (as
shipped — no flashing), on the same LAN as your laptop, and its IP address
(from your router, or a screen on the board: `ip addr show`). The board's
default login is user `ubuntu` (password: your board's provisioning docs, or
ask whoever set it up).

**Deep dive:** every step here is condensed from
[`../iq9-gemma-geniex/README.md`](../iq9-gemma-geniex/README.md), which has
the full session transcript, measured numbers, and three gotchas explained.
If a step fails, read its section there.

---

## Step 1 — SSH access without passwords

On your laptop (Git Bash on Windows):

```bash
ssh-keygen -t ed25519            # skip if ~/.ssh/id_ed25519 already exists
ssh-copy-id ubuntu@<BOARD-IP>    # Windows without ssh-copy-id: see below
```

Windows fallback: `type %USERPROFILE%\.ssh\id_ed25519.pub | ssh ubuntu@<BOARD-IP> "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"`

Then add to your laptop's `~/.ssh/config` (create the file if missing):

```
Host iq9
  HostName <BOARD-IP>
  User ubuntu
  IdentityFile ~/.ssh/id_ed25519
  ServerAliveInterval 30
  ServerAliveCountMax 4
```

**Verify:** `ssh -o BatchMode=yes iq9 'echo SSH_OK'` prints `SSH_OK` with no
password prompt. Every later command uses the `iq9` alias.

## Step 2 — Install the LLM (GenieX + Gemma 4 E2B)

All on the board (`ssh iq9`), in order:

1. Host libraries:
   ```bash
   sudo apt-get update
   sudo apt-get install -y libatomic1 libglib2.0-0t64 qcom-adreno1 qcom-fastrpc1
   ```
   ⚠️ **Two board gotchas** — if `apt-get install` complains about unmet
   dependencies, **never run `apt --fix-broken install`** (it removes the
   GStreamer stack the cameras need); use
   `apt-get download <pkg> && sudo dpkg -i <pkg>*.deb` instead. And do
   **not** install `ocl-icd-libopencl1` (conflicts with `qcom-adreno1`).
   If `libqnn1` is missing: `apt-get download libqnn1 && sudo dpkg -i libqnn1*.deb`.
2. GenieX CLI:
   ```bash
   curl -fsSL https://qaihub-public-assets.s3.us-west-2.amazonaws.com/qai-hub-geniex/install.sh | sh
   echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.profile
   ```
3. Pull the model (4.3 GB download):
   ```bash
   ~/.local/bin/geniex pull google/gemma-4-E2B-it-qat-q4_0-gguf
   ```
4. **Apply the required patch** (GenieX ≤ v0.3.18 mis-handles this model's
   text prompts; without this the model ignores everything you say):
   ```bash
   pkill -x geniex || true
   cd ~/.cache/geniex/models/google/gemma-4-E2B-it-qat-q4_0-gguf
   cp -n geniex.json geniex.json.bak
   python3 - <<'EOF'
   import json
   m = json.load(open("geniex.json"))
   m["ModelType"] = "llm"
   m["MMProjFile"] = {"Name": "", "Downloaded": False, "Size": 0}
   json.dump(m, open("geniex.json", "w"))
   EOF
   ```
   ⚠️ Re-apply after any future `geniex pull` of this model.
5. Smoke test (~70 s, loads the model once):
   ```bash
   ~/.local/bin/geniex infer google/gemma-4-E2B-it-qat-q4_0-gguf -c hybrid -p "Say hello in one short sentence." --max-tokens 40 --think=false
   ```
   Expected: a one-sentence greeting that actually answers the prompt.
6. Install the service so it runs forever. From the **laptop**, in the repo:
   ```bash
   scp infra/systemd/geniex-serve.service iq9:/tmp/
   ssh iq9 "sudo cp /tmp/geniex-serve.service /etc/systemd/system/ && sudo systemctl daemon-reload && sudo systemctl enable --now geniex-serve"
   ```

**Verify:** `ssh iq9 "curl -s http://127.0.0.1:18181/v1/models"` lists
`gemma-4-E2B`. (Endpoint appears ~8 s after start; the first request loads
the model, ~12 s.)

## Step 3 — Install the MQTT broker

1. On the board:
   ```bash
   apt-get download mosquitto mosquitto-common libmosquitto1 2>/dev/null; sudo dpkg -i mosquitto*.deb libmosquitto*.deb
   ```
   (Plain `sudo apt-get install -y mosquitto` is fine if apt is healthy on
   your board — the download+dpkg route is the gotcha-safe path.)
2. From the laptop, install our config (MQTT on `11883`, WebSocket on `19001`):
   ```bash
   scp infra/mosquitto.conf iq9:/tmp/
   ssh iq9 "sudo cp /tmp/mosquitto.conf /etc/mosquitto/conf.d/qnet.conf && sudo systemctl enable --now mosquitto && sudo systemctl restart mosquitto"
   ```

**Verify:** `ssh iq9 "ss -tln | grep -E '11883|19001'"` shows both listeners.

## Step 4 — Ship the code and make its venv

From the laptop, in the repo:

```bash
git archive HEAD --prefix=qnet-home/ | ssh iq9 'tar -x -C ~'
ssh iq9 "python3 -m venv ~/qnet-agent-venv && ~/qnet-agent-venv/bin/pip install aiomqtt httpx pyyaml openai"
```

## Step 5 — Board-local config

On the board, create `~/qnet-home/config/house.local.yaml` — the gitignored
overlay holding this board's secrets and address:

```bash
ssh iq9 "cat > ~/qnet-home/config/house.local.yaml" <<'EOF'
mqtt: { host: 127.0.0.1, port: 11883, ws_port: 19001 }
# Telegram values come from Guide 4 - the agent runs fine without them
# (notifications fall back to the console + data/outbox/telegram.log):
# telegram_bot_token: "123456:ABC..."
# contacts:
#   - { name: "Sarah", telegram_chat_id: "123456789" }
EOF
```

⚠️ Never copy a `house.local.yaml` from another machine — it is
board-specific by design (`verify/INCIDENT-wrong-broker.txt` is the
postmortem of what happens).

## Step 6 — Install the agent service

From the laptop:

```bash
scp infra/systemd/qnet-agent.service iq9:/tmp/
ssh iq9 "sudo cp /tmp/qnet-agent.service /etc/systemd/system/ && sudo systemctl daemon-reload && sudo systemctl enable --now qnet-agent"
```

**Verify (mandatory):**

```bash
ssh iq9 "journalctl -u qnet-agent --no-pager | grep connected | tail -1"
```

Must say **`connected 127.0.0.1:11883`**. Anything else → Step 5's config is
wrong.

## What you have now

The brain: an LLM on the NPU, the event fabric every device will talk on,
and the agent listening for falls and questions. All three restart
themselves on boot. Next: [Guide 3 — a room node](03-room-node-ventuno.md).
