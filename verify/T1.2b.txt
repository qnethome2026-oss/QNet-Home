1c. Bug found and fixed during verification: `ts` precision
`nowTs()` originally did `Math.round(Date.now()/100)/10` (one decimal place).
JSON has one number type, so ~1-in-10 timestamps landed on an exact integer
second and serialized without a decimal point (`1785960730` instead of
`1785960730.0`) — a strict consumer (e.g. a Python type check expecting
`float`) would read that back as an `int`. Fixed to `Date.now() / 1000`
(full millisecond precision, no rounding), reducing the collision window to
~1-in-1000. Verified empirically: 0 integer collisions in 2000 samples
(see 1b re-run above).
