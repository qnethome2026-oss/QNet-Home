WHAT CHANGED, AND WHAT DELIBERATELY DID NOT
--------------------------------------------------------------------
This was a LAYOUT + FEATURES evolution of checkpoint G's product page, not a
rewrite. Everything the brief said to keep is still the same code: the MiniMQTT
client (byte-identical, still the copy attributed to admin.html / dev/sim.html),
the qnet/session/<id> + qnet/<room>/* subscribe-and-index logic, humanize(),
deriveNames(), roomState(), houseStatus(), takeoverPredicate(), relativeTime(),
elapsedSeconds(), statusStripFacts(), conversationBubbles(), the help and
settings modals, the connection field, the takeover overlay, the AGPL footer
and the ?selftest=1 harness.

The one behavioural change inside the kept code is humanize()'s return shape:
`icon` (an emoji character) became `iconId` (a name in the inline SVG sprite).
It is still pure, still returns null for every admin-only event kind, and still
puts the word SIMULATED inside the sentence. Its self-tests were updated to
assert the new field, and a new case asserts that every iconId it can return
actually exists in the sprite - a typo'd name would otherwise ship as an empty
box on a page nobody looks at twice.

One other deliberate change: pressing Save in Settings no longer forces a
reconnect unless the hub address actually changed. Saving a room assignment
used to drop and re-establish the connection for no reason.

DESIGN CHOICES WORTH RECORDING

  * The plan is drawn ONCE in markup and only ever re-tinted by script. The
    geometry never moves, so a state change has nothing to reflow and nothing
    to get wrong at 3am. Script touches four things per room: a CSS class, a
    caption string, and two `is-off` toggles.

  * Walls are individual line segments with real door gaps, not five
    rectangles butted together. That is the whole difference between "a floor
    plan" and "a grid of boxes". 1.5px stroke, rounded outer corners (r=10),
    a front-door gap in the bottom wall and a doorway into each of the three
    top rooms, plus an open archway between Living Room and Kitchen. Quarter-
    circle door swings at 1px / 45% opacity say "this is a door" without
    competing with anything that matters.

  * Bathroom is 138 units wide against the bedrooms' 218, so it reads as the
    small room without needing a label to say so.

  * The alert pulse is 2s ease-in-out on opacity, not a strobe - DESIGN S14's
    "urgent but not a siren". It is disabled entirely under
    prefers-reduced-motion.

  * An unmonitored room's caption says "No device", never "All quiet". "All
    quiet" about a room nobody is watching would be a lie by omission.

  * Two devices in one schematic room resolve to the WORST of their states,
    using the same rank order the top bar's worst-room rule uses. Averaging an
    alert away was never an option.

  * MAPPING PRECEDENCE is saved override > shipped default > name similarity >
    Unassigned, and only the OVERRIDES are persisted, never the resolved
    result. A house that never opens Settings picks up any later improvement to
    the guesser; a house that DID open Settings keeps exactly the decision a
    person made. An override of "" is a deliberate "keep this off the plan" and
    is honoured as such rather than being silently re-guessed on next load.

  * Similarity is exact > prefix > containment > Dice coefficient over letter
    pairs, with a floor of 0.6. Deliberately conservative: putting a fall in
    the WRONG room on the map is worse than leaving a chip in the Unassigned
    row for someone to assign. "bath" and "kitchenette" are matched;
    "guest_room" and "utility" are not, and park.

  * The Summary card is labelled "Summary" with a sparkle and a
    "Generated from today's activity" tooltip. It does NOT claim a model wrote
    it, because no model did: composeSummary() is a deterministic pure function
    with 19 unit tests over it. The seam for a future qnet/summary message is marked
    ">>> SEAM <<<" in three places (the function's early return, the module
    variable, and the branch in the message handler) and is itself unit-tested.

  * SIMULATED is preserved in the recap sentence, not only the feed, and the
    renderer paints the same red badge on it in both places. S14's rule is
    about the reader, and the reader is the same person.

  * Icons are stroke-only on a 24x24 grid with NO fill/stroke attributes on any
    path, so every glyph inherits colour from the <use> that summons it. That
    inheritance is why there is no per-icon colour CSS in the file at all, and
    why the alert icon is red and the all-clear icon is green for free.
