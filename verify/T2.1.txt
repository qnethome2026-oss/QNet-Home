=== the one judgement call in this task, written down ==================
DESIGN §6's exit-resolution rule ("a phase id jumps, any other name ends the
session with that label") makes EVERY exit name legal, which would make
`escalat:` a silent session close - the single worst failure this file can
produce. The loader therefore keeps a vocabulary of terminal states
(ok, found, not_found, done, resolved, closed, cancelled - §6's own list plus
the two the engine itself produces), extensible per skill with a
`terminal_exits:` frontmatter list. A name that is neither a phase nor a known
terminal state is a load error. The RUNTIME rule is unchanged and is tested
directly (test_exit_resolution_rule): resolve_exit("escalate") -> ("jump",...),
resolve_exit("ok") -> ("end", "ok").

=== the registry is injected, never assumed ============================
`load_skill(path, tools=...)` takes the registry to validate against; the
default resolves qnet.tools.TOOLS lazily and, if it is not importable yet,
skips tool validation with a warning instead of refusing to start. Every test
passes its own fake registry (tests/test_skill_loader.py FAKE_TOOLS), so the
suite is hermetic with respect to another lane's task.
