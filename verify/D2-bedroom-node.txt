## 4. Design note — who exports the frame / heartbeat with NO vision on this board

stream.py deliberately never opens a camera: it serves what vision.py exports to
/dev/shm/qnet_<room>_frame.jpg — and vision (fall detection) stays kitchen-only.
So qnet/node/look.py gained an OPT-IN `--export-every S` flag (default 0 = off,
kitchen node unchanged): one background thread owns the camera, drains it
continuously, atomically writes the shm frame every S seconds (vision.py's
_atomic_write), and look.py publishes the 5 s qnet/<room>/status heartbeat
(state "look-only", detector "none (look+stream node)"). The bedroom unit runs
`--export-every 1`. Units were NOT templated — two explicit per-room files in
infra/systemd/ (qnet-look-bedroom.service, qnet-stream-bedroom.service),
installed on the board under the canonical names qnet-look/qnet-stream; the
kitchen files' comments already double as docs and a template would hide the
one real difference (the export flag).
