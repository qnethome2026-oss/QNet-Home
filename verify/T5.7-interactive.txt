WHAT CHANGED
--------------------------------------------------------------------

FEATURE 1 - typed replies behind a feature flag ("Simulated voice input")
  * Settings gains a "Simulated voice input" checkbox. Stored as
    qnethome.voicesim = "1"/"0"; decoded by parseVoiceSimFlag() in the LOGIC
    CORE, which returns true ONLY for exactly "1" - so a fresh page, a cleared
    value, "0", corrupt text and storage-disabled all mean OFF. DEFAULT OFF is
    a tested rule, not a habit (self-test + stub-DOM assertions below).
  * While ON: a red bold "SIMULATED VOICE" badge sits in the Live activity
    panel head (same .sim-badge treatment as the SIMULATED call badge - §14's
    honesty rule), and a composer docks under the feed: room selector + text
    input + Send. Room list = the discovered rooms the page already indexes;
    the default selection is the room of the most recent activity
    (defaultVoiceRoom(), pure, tested); a room a person picks explicitly is
    never re-guessed.
  * Routing is routeInput() in the LOGIC CORE - copied verbatim from
    dev/sim.html's ROUTING CORE (DESIGN §5 sanctions the sim as the stand-in
    for the unbuilt speech service), along with newUlid/normalize/
    matchesResponderPhrase/stripWakePhrase/buildAsk/buildHeard. The routing is
    therefore now duplicated in THREE places - qnet/node/voice.py, dev/sim.html
    and index.html - and both HTML files carry a "change all three" comment.
    Order of checks, identical to the sim: responder phrase (any state) ->
    qnet/<room>/ask kind=responder_brief text="" | active run in that room ->
    qnet/<room>/heard {text, silence:false} | wake phrase -> qnet/<room>/ask
    kind=query, phrase stripped | anything else -> NOT published, shown greyed
    in the feed with a "not heard — no active conversation" hint chip
    (mirroring the sim's discard row).
  * Every line that IS sent renders locally as
    'Typed in the <Room>: "..."' with the SIMULATED VOICE badge on the line.
    If the page is not connected, nothing false is implied: the line carries
    "not sent — this screen is not connected to your home" instead.

FEATURE 2 - room modal live camera preview (DESIGN §17 O14)
  * Each row in Settings > Rooms & devices gains a "Camera preview address
    (optional — stays inside your home)" field. Stored under qnethome.camurls
    (per discovered room, like the plan overrides; empty field = forgotten).
  * A drawn room's preview address = first of its device rooms with one saved
    (camUrlForRoom(), pure, tested). No address -> the modal shows EXACTLY the
    placeholder it always did ("Camera streaming is not enabled in this
    build" / "Coming soon").
  * With an address: the 16:9 slot shows the node's latest frame, re-fetched
    every 500 ms with a cache-busting ?t=<now> (camBustUrl(), pure, tested -
    appends &t= when the address already has a query). The label is
    "● LIVE — local preview (LAN only)" - honest per O14; the word
    "streaming" is not used for it anywhere.
  * On fetch error: a quiet "Camera unreachable — still trying" pill; the loop
    keeps retrying while the modal is open. The interval polices its own
    lifetime: the moment the room modal is not open - however it was closed
    (x, scrim, Escape) - the next tick shuts it down. No background traffic.

FEATURE 3 - Wire log in the admin portal
  admin.html previously showed sessions, room cards, latency, bytes and the
  per-topic COUNT table - but no raw message stream. Added: a "Wire log" card
  in the System tab (full-width, under Messages per topic): every raw MQTT
  message as it arrives, monospace "HH:MM:SS.mmm topic payload-JSON", NEWEST
  FIRST (matching the Activity list's "newest first" convention), kept lines
  capped at 500, with a Pause/Resume button (pauses RENDERING; capture
  continues underneath so resuming shows what arrived) and a filter input
  (case-insensitive substring over topic + payload). Jargon is fine there -
  it is the admin page; index.html's audit is unaffected.

JARGON ALLOWLIST: NOT changed. The in-page JARGON self-test and the T5.5
visible-text audit pattern were both re-run unmodified and still find zero
hits - "SIMULATED VOICE", the toggle label, the composer placeholder, the
camera strings and the hint chips contain no wire vocabulary, so no allowlist
addition was needed.
