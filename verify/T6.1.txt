Contract change made in this task
---------------------------------
contracts/mqtt.md: the `brief` log line, left explicitly unfrozen by T0.1 ("§6
gives no shape for it... it is settled in T6.1"), is now FROZEN:

  { "ts": <float>, "event": "brief", "ask_id": <string|null>,
    "spoken": <bool>, "text": <string, optional> }

  ask_id  the id of the `ask` that requested it - the only link back, since the
          brief is not a session and never appears on qnet/session/<id> as one
  spoken  true when the summary really was published to qnet/<room>/say
  text    the summary as spoken; optional, present whenever there was one
  Exactly one line per brief, only into a file that already existed (a no-history
  room is spoken to and nothing is written). The read itself
  (get_session_summary) deliberately logs no `tool` line: §12 allows the
  interrupt one line in the file it summarised, and this is it.

Also: dashboard/index.html's describeEntry now renders `brief` as e.text (it fell
through to e.note || e.state, which the frozen shape does not carry) - one line,
no behaviour change anywhere else.

Design ambiguities found and how they were resolved
---------------------------------------------------
1. §12's skill file has no `urgency` and no phases, but the T2.1 loader requires
   both. Resolved by a second loader (load_interrupt_skill -> InterruptSkill)
   rather than by weakening the phase loader: everything Skill guarantees (a
   first phase, resolvable exits, a validated allowlist) is meaningless for an
   interrupt, and a phase engine handed one should fail loudly.
2. §12 says "prio safety if a session is live". Refined to *a live **safety**
   session*: a find session in the room is not something the brief must speak
   over, and §12 is scoped to fall response. Everything else gets `routine`.
3. `say.prio` had no value for "neither safety nor the fall comfort loop", so
   T6.2 added `routine` (see verify/T6.2.txt). The brief uses it.
4. The brief line's home when the summarised file is not the agent's current
   session for that room (a restart, or a find session since opened in the same
   room): the line is appended straight to the file, because the file is the
   record. When it *is* the live session, it goes through the normal record path
   so the dashboard sees it too.
5. Names. The first live run produced "Sarah said my hip hurts" - the 2B model
   blurring the resident and the contact, from a fact that read 'they said "..."'.
   Fixed at the source (the facts now say 'Margaret said "..."' and 'the contact
   Sarah was messaged'), not by post-processing, plus one prompt rule. Re-run
   live: correct in both briefs. This is exactly the class of error the
   "facts in, wording out" seam is meant to make fixable.
